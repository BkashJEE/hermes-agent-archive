Generate the memory vault from a database instead of letting the agent edit it

Use structured model output as input to a deterministic store, then render a read-only Obsidian view.

By @lauratom · Discord

I just have my DB auto-generate a read-only Markdown vault

— @lauratom, 2026-04-04, via the public Nous Discord archive.

The contributor uses the model to extract structured semantic signals. A Python backend turns those signals into typed nodes and edges in SQLite FTS5, handles memory changes in SQL, and generates Markdown for viewing in Obsidian. The generated vault is an output, not the writable source of truth.

Limitations: Requires a custom memory backend; no complete implementation is supplied in the message. Read-only generated files alone do not establish a security boundary. Built-in Hermes session search already uses SQLite; that alone is not the trick.

Documentation check: this specific community technique was not found in the official English reference snapshot (5458de9) or the cached prompt guides. Related built-in features are documented. This is a bounded source review, not a claim about every document or independent execution testing.
