display.cli_layout picks how the classic CLI draws. The default, modern , prints everything in the scrollback as plain rows that start with one glyph and never depend on the terminal width, so resizing the window can't garble earlier output: A 40-column bar opens each user message and answer (accent) and each reasoning block (dim); reasoning streams live as in classic and ends with a ∴ Thought for 3s · <title> line. ❯ your message, ● a finished tool call ( ✗ in red when it failed, with its exit code), │ an edit's diff under its row, ☤ the answer, and ─ the turn's summary line. The composer's top rule carries the live activity (spinner, what's running, elapsed time, streamed tokens) on the left and the session title on the right; no spinner row is printed into the scrollback. The status line sits under the composer: the same fields as the classic status bar (model, context, cache hit, latency, tokens/s, background work, goal, duration, YOLO…) plus the working directory (with git branch) on the left; the keys that do something right now on the right.
