## Keep, omit and timing

Keep: practical purpose, who benefits, original attribution, local use, one contribution
question and a working link. Put the repo in the first reply for a short X post.

Omit: unverified engagement, unsupported claims of "best" or "complete", guaranteed results,
security-audit claims, official affiliation, an MIT claim about all third-party content,
and screenshots of plugin functionality that is not implemented.

Do not lead with counts; they become stale and do not explain the product. If a count is
used, derive it from the exact deployed data and distinguish stored from displayed entries.

Post the website announcement when its reviewed changes are live. Announce the plugin as
supported only after a versioned host-app test. Respond to workflow suggestions with a
request for their original source, then review them through issues/PRs. Posting, replies,
release tags and catalog submission are separate owner actions; none are performed by
preparing this file. No draft can promise a particular number of replies, followers or shares.
